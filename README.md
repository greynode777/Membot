# Solana Alpha Bot v5 — Postgres + добавление токенов через Telegram

Новое в этой версии:

1. **Постоянное хранилище (Postgres)** — если вы подключите бесплатную
   базу Postgres в Railway, список отслеживаемых токенов, "подтверждённые"
   токены и история трендов **больше не будут стираться** при каждом
   редеплое. Если Postgres не подключена — бот автоматически продолжает
   работать на локальных файлах, как раньше (ничего не сломается).
2. **Добавление токена прямо из Telegram** — больше не нужно вручную
   редактировать `watchlist.json`. Просто отправьте боту сообщение с
   адресом токена (mint address) — он сам проверит, что это похоже на
   настоящий адрес, добавит в список отслеживания и подтвердит в ответ.

---

## Шаг 1. Подключите Postgres в Railway (рекомендуется)

1. Откройте ваш проект в Railway.
2. Нажмите **"New"** (обычно кнопка сверху или "+") → **"Database"** →
   **"Add PostgreSQL"**.
3. Всё. Railway сам создаст базу и подставит боту переменную окружения
   `DATABASE_URL` — ничего вписывать вручную не нужно.
4. При следующем запуске (или редеплое) бот сам создаст нужные таблицы —
   в логах появится строка `[db] Postgres подключена, таблицы проверены/созданы.`

Если вы **не** подключите Postgres — бот всё равно будет работать,
просто данные будут храниться в файлах внутри контейнера и обнуляться
при редеплое (как в предыдущих версиях).

---

## Шаг 2. Добавление токенов для отслеживания — через Telegram

Раньше нужно было редактировать `watchlist.json`. Теперь достаточно:

1. Открыть чат с вашим ботом в Telegram (тот же, куда приходят алерты).
2. Отправить сообщение — просто адрес токена, например:
   ```
   EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v
   ```
3. Бот ответит:
   - ✅ если адрес похож на настоящий и данные по нему нашлись —
     подтвердит добавление;
   - ⚠️ если это не похоже на адрес Solana-токена — скажет об этом;
   - ⚠️ если адрес похож на настоящий, но пока нет данных на DexScreener
     (например, у токена ещё нет ликвидности) — всё равно добавит и
     проверит позже автоматически.

Бот реагирует **только на сообщения из чата, указанного в
`TELEGRAM_CHAT_ID`** в `config.py` — то есть только вы можете добавлять
токены таким образом, случайные сообщения от других игнорируются.

`watchlist.json` по-прежнему можно редактировать вручную — это работает,
только если Postgres **не** подключена (файл — резервный вариант хранения).

## Остальное — как в предыдущей версии

- Первый алерт при запуске бота
- Почасовой отчёт (проверено / рагпул / рекомендовано)
- Мгновенный алерт при нахождении хорошего нового токена (с расшифровкой
  всех показателей)
- Автоматическое добавление рекомендованных токенов в 12-часовую
  перепроверку с алертом "растёт/падает"
- Подтверждение доставки Telegram-сообщений с повтором каждые 15 секунд

## Загрузка на GitHub и запуск на Railway

1. Загрузите все файлы проекта на GitHub (как раньше).
2. Railway → Deploy from GitHub repo.
3. Подключите Postgres (Шаг 1 выше) — можно в любой момент, даже после
   первого запуска, бот подхватит базу при следующем перезапуске.
4. Впишите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `config.py`,
   если ещё не сделали.

## Если бот падает с ошибкой "Crashed" и libpq.so.5

Если после подключения Postgres бот падает при запуске с ошибкой вида
`ImportError: libpq.so.5: cannot open shared object file` — это известная
особенность сборщика Railway: он не всегда ставит системную библиотеку,
нужную для работы с Postgres, только через `requirements.txt`.

**Решение уже включено в этот проект**: файл `nixpacks.toml` в корне
репозитория явно указывает Railway поставить нужную библиотеку:

```toml
[phases.setup]
aptPkgs = ["libpq5"]
```

Если вы уже загружали проект на GitHub раньше — просто добавьте этот
файл (`nixpacks.toml`) в репозиторий и загрузите заново (или через "Add
file" → "Upload files" на GitHub) — Railway пересоберёт проект
автоматически.

## Что можно настроить в config.py

Все прежние настройки (интервалы сканирования, пороги баллов, интервал
повтора Telegram) плюс ничего нового настраивать не нужно для Postgres —
она подключается автоматически через `DATABASE_URL`.

## Важные оговорки

- LP-lock, wash trading и wallet clustering по-прежнему TODO-заглушки в
  коде — более глубокие проверки добавляются отдельно по мере необходимости.
- Если вы очень быстро отправите несколько адресов подряд в Telegram,
  бот обработает их по очереди (не параллельно) — задержка обычно не
  больше пары секунд на сообщение.
- Функция удаления токена из отслеживания через Telegram (например,
  командой) пока не реализована — но обработчик в коде (`watchlist.remove`)
  уже готов на будущее, можно добавить команду `/remove <адрес>` по запросу.
