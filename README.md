# Solana Alpha Bot v11 — фильтр 2ч + наблюдение с проверкой улучшения

## Как теперь работает бот

Вместо сканирования токенов в первые минуты жизни (это был предыдущий
подход) — теперь **бот игнорирует токены младше 2 часов вообще**. Логика:

```
Обнаружение токена (DexScreener)
        │
        ▼
   ОЖИДАНИЕ (pending) — токену ещё нет 2 часов, ждём
        │  (как только исполнилось 2 часа)
        ▼
Считаем Fundamentals Score
        │
        ├── < 40% ──────────────► ОТСЕЯН НАВСЕГДА
        │                          (больше никогда не сканируется)
        ▼ ≥ 40%
   НАБЛЮДЕНИЕ (observed)
   Проверка каждые 2 часа
        │
        ▼ после 3-го скана:
   Фундаментал вырос на 10+ процентных пунктов
   относительно момента постановки на наблюдение?
        │
   ┌────┴────┐
  ДА          НЕТ
   │           │
   ▼           ▼
🚨 АЛЕРТ   продолжаем наблюдение
рекомендация  ещё 3 скана (итого 6)
   │           │
   ▼           ▼ после 6-го скана:
Переход в    улучшение есть?
12ч-мониторинг  │
(как раньше) ┌──┴──┐
            ДА     НЕТ
             │      │
             ▼      ▼
          🚨 АЛЕРТ  ОТСЕЯН
                    НАВСЕГДА
```

Каждый адрес токена, попавший в эту систему в ЛЮБОМ статусе (включая
"отсеян навсегда"), больше никогда не обрабатывается повторно, даже
если снова появится в списках DexScreener.

---

## Циклы, которые запускает бот

1. **Обнаружение** (`candidate_discovery_loop`) — раз в 15 минут ищет
   новые токены на DexScreener, регистрирует их как "ожидающих".
2. **Первичный фильтр** (`candidate_pending_loop`) — раз в 15 минут
   проверяет, не исполнилось ли кому-то из ожидающих 2 часа; если да —
   считает Fundamentals Score и решает: в наблюдение или отсев.
3. **Наблюдение** (`candidate_observed_loop`) — раз в 15 минут проверяет,
   не пора ли кому-то из наблюдаемых токенов на очередную 2-часовую
   проверку (у каждого токена свой персональный таймер каждые 2ч).
4. **Watchlist** (`scan_established_loop`) — как раньше, токены, которые
   вы вручную добавили (через Telegram или `watchlist.json`), проверяются
   каждые 5 минут.
5. **12ч-мониторинг** (`confirmed_recheck_loop`) — токены, получившие
   рекомендацию (из нового пайплайна или ранее), проверяются каждые 12ч.
6. **Почасовой отчёт** и **приём сообщений Telegram** — как раньше.

## Что можно настроить в config.py

```python
CANDIDATE_MIN_AGE_HOURS = 2                  # минимальный возраст для оценки
CANDIDATE_INITIAL_THRESHOLD_PCT = 40         # порог первичного фильтра (%)
CANDIDATE_RECHECK_INTERVAL_HOURS = 2         # раз в сколько часов наблюдение
CANDIDATE_CHECKPOINT_SCANS = 3               # после какого скана проверяем улучшение
CANDIDATE_MAX_SCANS = 6                      # финальная проверка
CANDIDATE_IMPROVEMENT_THRESHOLD_PCT = 10     # на сколько % пунктов должен вырасти скор
```

Если пороги покажутся слишком строгими/мягкими после наблюдения за
реальными токенами — просто поменяйте цифры.

## Установка (как раньше)

1. Загрузите файлы на GitHub, разверните на Railway.
2. В Railway → Variables добавьте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`,
   опционально `HELIUS_API_KEY` и `DATABASE_URL` (см. предыдущие версии
   README, если ещё не настроено).
3. При первом запуске бот создаст новую таблицу `candidates` в Postgres
   автоматически (или будет использовать `candidates.json`, если базы нет).

## Важные оговорки

- Discovery использует те же источники DexScreener (`boosted`/`profiles`),
  что и раньше — это списки "продвигаемых"/недавно добавленных токенов.
  Токен должен появиться там, чтобы бот вообще его заметил — тотального
  сканирования "всех токенов Solana" нет и не может быть на бесплатных API.
- Возраст токена считается от `pairCreatedAt` (реальное время создания
  торговой пары на DexScreener), а не от момента, когда бот его заметил.
- LP-lock, RugCheck, анализ бандлов, funding-кошельков, кластеров,
  поведения дева, alpha-кошельков — по-прежнему не реализованы (см.
  `scoring.py`, класс `RiskSignals` — оставлен в коде для новых токенов,
  на будущее, но эта система для 2ч-фильтра сейчас не используется).
